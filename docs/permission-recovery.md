# アクセシビリティ登録の復旧 — 2026-10-29

許可のスイッチがオンで、登録先が `/Applications/WindowHub.app` でも一覧が0件になる事象を確認しました。macOSのTCCログに、WindowHubの既存のコード要件と現行アプリの署名が一致しないエラーが記録されていました。アプリ更新により旧版への許可がオン表示のまま残っていたことが原因です。単純にユーザーが許可していないとした以前の説明を訂正します。補助プロセスへの帰属は親アプリのWindowHubで、別の補助アプリへの権限付与が原因ではありませんでした。

ユーザーの明示承認後、WindowHubを終了し、システム設定でWindowHubだけを削除しました。ユーザーによるTouch ID認証後、現在の `/Applications/WindowHub.app` を再追加・有効化して起動しました。アプリの再ビルド・再署名は行っていません。他のアプリの権限は変更していません。

本番アプリのHomeで3画面・7ウィンドウを取得し、Arrangeに実際のウィンドウ一覧が出ること、Quick Moveに起動直前の対象が表示されることを確認しました。ユーザーの実ウィンドウの配置は変更していません。

ローカル開発用のad-hoc署名では、更新後に再登録が必要になる場合があります。オン表示なのに拒否されるときは、設定の追加先だけでなくTCCの署名不一致を確認します。確認中に再ビルドすると再び署名が変わるため、権限復旧の検証中はアプリ本体を変更しません。継続配布での安定した署名はDeveloper IDによる配布手順を別途準備する必要があります。
