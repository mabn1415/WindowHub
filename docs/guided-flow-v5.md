# WindowHub v5 操作フロー改善

2026-10-29。このMacにインストールする変更の記録です。

## コンパクトなポップアップ

ホームは520×270（ヒントを出す場合は520×300）に縮小し、設定項目と画面数などの補助情報を外しました。設定はCommand＋,（WindowsはCtrl＋,）で開き、Escで戻ります。開くたびにマウスのある画面を選び、作業領域の中央に表示します。表示中は同じ画面に留まります。ドラッグ領域を削除し、macOSのNSWindowでも移動を無効化しました。サイズ変更・最大化・最小化を無効化し、macOSのDockに常駐しない補助アプリとして扱います。

開発版の実ウィンドウで520×270、EV2785の作業領域中央（原点700,-660）を測定しました。ヘッダーをドラッグしても同じ座標でした。Command＋,とEscで設定からホームへ戻ることを確認しました。

## ホームの連続配置

ホームを開いたまま、← →で左右、↑ ↓で上下、Enterで最大化します。左右の押し直しではモニター間を移動し、押し直しの時間制限はありません。配置のたびにハブは閉じず、Escで終了します。対象アプリ名、キーのヒント、配置後のモニター名を表示します。キーを素早く押した場合は順番に処理します。長押しの自動リピートはモニターの意図しない巡回を防ぐため抑止します。

開発版の実アプリで、専用ウィンドウだけを対象に左半分・間隔を空けた左連打で別モニターへ移動・右半分・上下・最大化を実測しました。Escでハブが非表示になり、対象アプリへ戻ることを確認しました。

## 変更

1. アプリ選択 → ディスプレイ選択 → 配置決定の順を固定。先の段階は無効化し、Enterで各決定を進めます。領域番号だけで対象を勝手に割り当てる旧動作は廃止しました。配置の追加後に最初の段階へ戻り、Ctrl＋Enterで全件を一括反映します。Escでひとつ戻り、Editから戻っても選択と下書きを保ちます。
2. ディスプレイの実配置図と、番号・名前・上下左右の位置・解像度のカードを追加。Quick Moveでは移動先を大きな見出しにも表示します。
3. ハブを開かずに使える5つの直接キーを追加。左右は現在の位置に応じてモニター間を循環し、押し直す時間に制限はありません。長押しによる連続移動を抑止し、処理は順番に実行します。キーは個別に変更・永続保存でき、重複・登録失敗時は既存キーを維持します。
4. ハブを出す画面はマウス位置・操作中ウィンドウ・メイン画面から選択。標準はマウス位置で、表示中の画面切替では位置を固定します。[Raycast公式設定](https://manual.raycast.com/settings)の選択肢を参照しました。
5. Delete / MacのBackspaceで選択領域を削除。入力欄の文字編集と区別します。最大化は作業領域いっぱいへの配置です。

## 検証済み範囲

- React / TypeScript本番ビルド、Tauri macOS arm64リリースビルド、アプリ署名検証。
- TypeScript単体テスト15件、Rust単体テスト16件。
- ブラウザー操作テスト12件。順序の強制、Esc、重ね配置、保存した初期レイアウトの保護、Delete / Backspace、Quick Moveの移動先、キー・表示先設定の保存、標準840×610でのボタン表示を確認。
- 専用テストアプリのみを対象にしたmacOS統合検証1件。実際の3画面で左右・連打移動・上下・最大化を実測し、元の位置へ戻しました。普段使うアプリは移動していません。
- Windows管理処理と共有モデルのx86_64-pc-windows-msvc向けコンパイル検査。Windows版Tauri全体のビルド、インストーラー作成、実キー・実ウィンドウ操作は未検証です。

初回は物理キーの受信を確認できませんでした。その後、現在ユーザーが設定している直接キー（Ctrl＋Command＋1〜4、Ctrl＋Command＋Enter）で再確認し、左右・上下・最大化と左右の連打によるモニター移動が動作しました。前回案内した標準キーと現在の設定キーは異なります。shortcut-diagnostics.jsonには登録済みショートカットID・受信段階・時刻を直近32件だけ記録し、通常の入力内容やウィンドウタイトルは記録しません。

## 配布上の注意

このローカルMac版はad-hoc署名です。更新で署名が変わると、アクセシビリティ許可がオンでも旧版の登録が残り、現行版が拒否される場合があります。ユーザー承認後、WindowHubだけを現行の /Applications/WindowHub.app に再登録します。安定配布用Developer ID署名・公証は未実装です。

学習は既存のローカル履歴に基づくルール提案のみです。普段の手動配置の自動観察・高度な機械学習は未実装です。
