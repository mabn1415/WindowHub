# WindowHub

macOS / Windows共通の、キーボード中心ウィンドウ配置アプリです。Tauri 2、React / TypeScript、Rustで構成しています。現在のビルドはApple Silicon Mac用です。

## macOSにインストール・更新

ターミナルで次の2行を実行すると、依存関係の準備、ビルド、`/Applications/WindowHub.app` への配置、起動まで行います。

```sh
cd ~/Documents/WindowHub
./install.sh
```

事前にNode.js 22以降、npm、Rust stable、Xcode Command Line Toolsが必要です。プロジェクト内の `.tools/` にRustがある場合はそれを使います。インストーラーは不足しているソフトを勝手にインストールせず、必要なものを表示します。依存関係の取得にはインターネット接続が必要です。Apple Silicon Macで確認しています。Windows用ではありません。

前のWindowHubがある場合は `work/install-backups/` にアプリのコピーを残します。設定や保存したレイアウトは引き継がれます。ビルドに失敗した場合、インストール済みのアプリは変更しません。同名の別アプリやファイルは上書きしません。

作成済みアプリを再利用する場合は `./install.sh --use-built` と実行できます。ビルド済みの `src-tauri/target/release/bundle/macos/WindowHub.app` が必要です。同一のアプリがすでに入っていれば、再配置を省略します。

### 初回・更新後の許可

ウィンドウの一覧取得と移動には、**システム設定 → プライバシーとセキュリティ → アクセシビリティ** で `/Applications/WindowHub.app` を許可してください。権限の変更とTouch ID認証はご自身で行います。許可後にWindowHubの「許可を確認」を押し、必要に応じて終了・再起動します。

このアプリは開発用の署名で作成されるため、更新後に許可がオンでもmacOSが新しい版を拒否する場合があります。その場合はWindowHubを終了し、同画面のWindowHubの登録だけを削除して、現在の `/Applications/WindowHub.app` を追加し直してください。権限を再登録しても未許可と表示される場合は、復旧確認が必要です。一括インストールで権限の問題が自動解決するわけではありません。詳しくは `docs/permission-recovery.md` を参照してください。

## このMacで使う

`/Applications/WindowHub.app` を開きます。通常利用はアプリケーション側を使います。通常はメニューバーに常駐します。

1. 初回ガイドをEnterで閉じます。
2. 権限案内からmacOSの「システム設定 → プライバシーとセキュリティ → アクセシビリティ」を開き、**WindowHub** を許可してください。許可後はハブを開き直すか「許可を確認」を押します。表示が変わらない場合はWindowHubを終了・再起動してください。追加する対象は `/Applications/WindowHub.app` です。
3. 対象アプリへ戻り、**Ctrl＋Shift＋Space** でハブを開きます。既に保存した起動キーがある場合は、そのキーが維持されます。ホームを開いたまま **← →** で左右、**↑ ↓** で上下、**Enter** で作業領域いっぱいに最大化できます。左右を押し直すとモニター間を移動します。ホーム操作では押し直すまでの時間制限はありません。**Esc** で終了します。機能画面はA / Q / E / S、またはTabでボタンを選んでEnterで開きます。設定は **Command＋,**（WindowsはCtrl＋,）で開きます。
4. **A** でArrange。**↑↓ → Enter**でアプリを選び、**ディスプレイの番号**で移動先を選びます。最後に**領域の番号 → Enter**で配置を追加します。手順を飛ばすことはできません。同じ領域へ複数を割り当てると、完全に同じ位置・サイズで重なります。
5. 配置決定画面で **R** を押すとEdit。矢印で5%、Shift＋矢印で1%ずつ比率を調整します。**[ / ]** で分割線を切り替えられます。
6. 配置を追加し終えたら、**Ctrl＋Enter** または「N件を一括配置」でまとめて反映します。**Esc**は手順をひとつ戻します。成功するとハブを閉じ、元のアプリへフォーカスを戻します。
7. 保存する場合は名前を入力し「初期として保存」または「別名保存」を選びます。画面上の下書きを変更しただけでは保存済み配置は変わりません。

**F6** で配置操作とボタン・入力欄の操作を切り替えます。ボタン操作側ではTab / Shift＋Tabで移動し、Enterで実行できます。**?** で操作ガイドを開きます。

## 画面

| 画面 | Homeからのキー | 用途 |
|---|---|---|
| Arrange | A | 複数モニターへの割り当て・プレビュー・一括配置 |
| Quick Move | Q | ハブを開く直前のウィンドウを即配置 |
| Edit Layout | E | モニター別の領域・独立した分割比率を編集 |
| Saved Workspaces | S | 初期レイアウト、用途別保存、履歴からの候補 |
| Settings | Command＋, / Ctrl＋, | 外観・キー操作 |

Homeに検索バー・スローガン・設定項目は置いていません。ハブは開くたびにマウスカーソルのあるディスプレイを選び、その作業領域の中央に表示します。ドラッグ移動とサイズ変更を無効化したポップアップです。macOSはDockに常駐せず、メニューバーのアイコンから開けます。Settings → キー操作で「マウスカーソルのある画面」「操作中のウィンドウがある画面」「メイン画面」を選べます。表示先はハブを開いた時点で固定し、画面遷移中は追従しません。これは[Raycastの表示先設定](https://manual.raycast.com/settings)に合わせた選択肢です。表示中はウィンドウとWebViewの両方にフォーカスを渡します。他アプリへ切り替えた際はハブを閉じ、その切替先からフォーカスを奪い返しません。Escで閉じた際は直前のアプリへ戻します。取得できない場合はメインモニターへ表示します。

標準サイズはHome 520×270（ヒント表示時は520×300）、Arrange / Edit 840×610、Quick Move 680×560、Settings 760×620です。作業領域に合わせて縮小し、小さい画面では内容をスクロールできます。


## ハブなしのQuick Move

WindowHubを起動して常駐させ、対象アプリを操作中に使います。このMacで直接キーによる左右・上下・最大化と、左右の連打によるモニター移動を実ウィンドウで確認しました。設定済みのキーが標準キーと異なる場合は、設定画面に表示されたキーを使ってください。標準キーは他の配置ソフトと重なりにくい組み合わせです。Settings → キー操作から5つそれぞれのキーを変更・記録・保存できます。

| 操作 | Macの標準キー | Windowsの標準キー |
|---|---|---|
| 左半分 / 右半分 | Ctrl＋Option＋Command＋← / → | Ctrl＋Alt＋Win＋← / → |
| 上半分 / 下半分 | Ctrl＋Option＋Command＋↑ / ↓ | Ctrl＋Alt＋Win＋↑ / ↓ |
| 作業領域いっぱいに最大化 | Ctrl＋Option＋Command＋Enter | Ctrl＋Alt＋Win＋Enter |

最大化はメニューバーやDockを通常どおり使える配置です。別Spaceへ移動する全画面表示ではありません。左右は現在の位置を確認し、同じ側にある場合は次のモニターへ移ります。押し直す間隔に制限はありません。画面中央の左右順で循環し、上下に並んだ画面は中央座標と高さの順に含めます。押しっぱなしではモニターを移しません。手動で左右半分に配置した場合も、その位置から別のモニターへ移動できます。

Home → Qでは、番号・画面名・位置図を見て移動先を選べます。1=左、2=右、3=上、4=下、5=最大化、6=3分割、7=4分割です。Ctrl＋Tabで移動先を切り替えます。ハブの表示先と、移動するウィンドウの対象画面は別々に扱います。

Editでは領域を選んで **Delete / Backspace** で削除できます。名前入力中のDeleteは文字だけを消します。最後の1領域は残ります。

## 分割・重ね配置と保存

モニターごとに1領域、左右2分割、上下2分割、3列、4分割を設定できます。さらに選択した領域を左右・上下へ分割でき、最大9領域です。分割線はそれぞれ独立して調整できます。領域の最小寸法はモニターの幅・高さの5%です。1台を70:30、別の1台を55:45にするなど、各モニターを別々に編集できます。

各領域には複数ウィンドウを割り当てられます。分割と重ね配置を同じモニター内でも組み合わせられます。アプリの最小サイズ等により指定どおりにならない場合は、個別の実測結果を表示します。

モニターのID・座標・作業領域・倍率ごとに初期レイアウトとワークスペースを記憶します。保存配置を読み込んだだけではウィンドウを動かしません。起動中の同じアプリへタイトル優先・同一アプリ内順序で割り当て直し、ArrangeでCtrl＋Enterを押すと反映します。未起動アプリや内部のタブ・ファイルは開きません。

- 初期レイアウトは明示的な「初期レイアウトを更新」で更新します。一時編集・適用・学習候補は上書きしません。
- 画面を戻っても下書きは保持し、ハブを閉じると未保存の下書きを破棄します。
- モニター接続変更時は通知して再取得を求め、古い座標への反映を拒否します。接続だけで自動移動はしません。
- 以前の版の保存形式は維持して読み込みます。任意矩形の旧形式で分割編集を使う場合は、パターンを選び直してください。
- モニター識別情報だけが異なる類似構成は、保存一覧から明示的に読み込めます。対応関係が曖昧な構成は流用しません。

## テーマ・起動キー

Olive Graphite、Clay & Stone、明色のSandstoneを用意しています。背景・パネル・境界線・文字・補助文字・アクセント・選択背景をHEX入力またはカラーピッカーで変更でき、背景の濃さ（55〜100%）・角丸・アニメーションも保存できます。macOSでは背景にぼかしを加えた半透明表示です。文字やボタンの不透明度は下げません。文字のコントラストが低い場合は警告します。

Command＋,で設定を開き、「キー操作」で、起動キーの記録・登録・リセット、ガイドの通常 / コンパクト / 非表示を設定できます。新しいキーを登録してから旧キーを解除するため、登録に失敗しても旧キーを維持します。OSや他アプリに予約されたキーは登録できない場合があります。

## 履歴と提案

ルールベースの提案を実装しています。有効時は成功した配置と「現在の実配置を記録」で明示的に取り込んだ手動修正を、モニター構成別に最大200件保存します。同じアプリ・配置の記録が2回以上ある候補について、頻度、14日半減の新しさ、現在開いているアプリの一致度で並べます。提案は保存一覧から読み込み、プレビュー後に適用します。

履歴にウィンドウタイトル・入力内容・文書内容は保存しません。ユーザーが明示保存したワークスペースには、再照合用のウィンドウタイトルが含まれます。いずれもローカル保存で、外部送信しません。Settingsから記録の停止・件数確認・履歴とそのバックアップの削除ができます。保存した初期レイアウトは履歴削除の対象外です。

**未実装:** 普段の移動の自動観察、時刻等を含む学習、高度な機械学習、無確認での自動配置、クラウド同期。

## 開発

Node.js 22以降、npm、Rust stable、各OSのTauriビルド環境が必要です。macOSはXcode Command Line Tools、WindowsはMSVC C++ビルドツール・WebView2を使います。

```sh
cd ~/Documents/WindowHub
npm ci
./run.sh dev
./run.sh build --bundles app
```

`run.sh` は、このMacのプロジェクト内 `.tools/` にRustがあれば選択します。通常のRust導入環境では `npm run tauri -- dev` / `npm run tauri -- build` を使えます。Windowsは `npm ci` → `npm run tauri -- build --bundles nsis` です。Mac上でWindowsインストーラーは作成していません。

```sh
npm test
npm run test:ui
cargo test --manifest-path src-tauri/Cargo.toml
# ロックされていないmacOSデスクトップ・実行元のアクセシビリティ許可が必要
python3 scripts/native-smoke.py
# Windows APIモジュールのみの型検査
cargo check --manifest-path scripts/windows-check/Cargo.toml --target x86_64-pc-windows-msvc
```

UIテストはGoogle Chromeを使用します。`npm run dev` をブラウザーで開いた場合は、明示したサンプルデータのUIプレビューとなり、実ウィンドウを動かしません。ネイティブ検証スクリプトは専用アプリのウィンドウだけを操作します。

## データと構成

macOS設定フォルダは `~/Library/Application Support/local.windowhub.desktop/`、Windowsは通常 `%APPDATA%\local.windowhub.desktop\` です。`settings.json` に設定・保存配置、`history.json` に履歴を保存します。書込みは一時ファイルからの置換と前回バックアップを使います。壊れた設定ファイルは読み込み時に上書きしません。

| ファイル | 役割 |
|---|---|
| `src/App.tsx` | 共通画面、画面履歴、キーボード操作 |
| `src/zones.ts` / `components/ZoneCanvas.tsx` | 再帰分割・割り当て・独立境界編集 |
| `src/themes.ts` / `style.css` | 共通テーマと外観 |
| `src-tauri/src/main.rs` | 起動キー・常駐・検証・コマンド |
| `src-tauri/src/model.rs` / `regions.rs` | データ・座標・保存照合・領域の検証 |
| `src-tauri/src/history.rs` / `store.rs` | 履歴候補・ローカル保存 |
| `src-tauri/src/platform/` | macOS / Windowsのウィンドウ操作アダプター |
| `src-tauri/native/WindowHubBridge.swift` | macOS Accessibility / Cocoa連携 |
| `docs/` | 引き継ぎ仕様書・構成・UI・キー操作 |
| `VERIFICATION.md` | 検証結果と制約 |

## 現在の制約

- ビルド済みMacアプリはad-hoc署名です。Developer ID署名・公証は行っていません。通常起動アプリのアクセシビリティ許可はユーザー操作が必要です。
- macOSの別Space、最小化中、特殊ダイアログ等は操作対象外です。ネイティブ全画面は対応するアプリだけに要求します。全画面中の通常配置は、全画面を解除してから行ってください。最大化は作業領域いっぱいへのリサイズです。
- WindowsはWin32の移動・サイズ変更・最大化を実装し、APIモジュールの型検査を通しました。実機起動、DPI混在、管理者権限差、仮想デスクトップ、インストーラーは未検証です。アプリ共通の真の全画面は提供せず、理由を表示します。
- 一括配置は順次実行です。一部だけ失敗することがあります。成功と失敗を分けて表示し、全成功の場合だけ一括配置を履歴へ記録します。
- OS制約やアプリ独自の最小サイズは回避しません。別プロセス・閉じたウィンドウへの誤操作を避けるため、反映直前にID・PID・アプリID・モニター構成を確認します。
- 自動起動、自由なハブ位置・寸法設定、機能ごとのキー再割り当て、除外アプリ、設定インポート / エクスポート、Redoは未実装です。

## アプリ一覧が空の場合

A / Qはアプリを起動するキーではなく、配置画面を開くキーです。「権限が未許可」の場合は他アプリを取得できません。アクセシビリティでアプリケーション側のWindowHubを許可してください。「許可を確認」は取得用プロセスも読み直します。許可しても表示が変わらない場合は、登録対象の場所を確認し、WindowHubを終了・再起動します。

Quick Moveは対象アプリを前面にしてからWindowHubのグローバル起動キーで開いてください。Raycastから起動した直後はRaycastが直前のアプリになる場合があります。

### 更新後、許可がオンでも0件になる場合

ad-hoc署名の更新で旧版の許可が残ると、オン表示でもmacOSが現行版を拒否することがあります。WindowHubを終了し、アクセシビリティのWindowHubだけを削除して、現在の `/Applications/WindowHub.app` を追加し直して起動します。権限の変更とTouch ID認証はユーザーの承認・操作が必要です。復旧確認中に再ビルド・再署名しないでください。詳細は `docs/permission-recovery.md` を参照してください。
